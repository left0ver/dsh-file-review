# 发布说明章节

Release 只允许使用以下两个二级章节，并按此顺序输出：

1. `## ✨ Features` — 新增或显著扩展用户可见的能力、工作流或公共 API。
2. `## 🐛 Bug Fixes` — 修复错误行为、回归、崩溃或用户可见的兼容性问题。

commit 标题、正文、文档差异、变更文件和必要的当前代码都是判断依据，任何单个关键词都不能单独决定分类。一个用户可见的功能或修复可以由多个相关 commit 共同构成。

省略内部维护、重构、测试、CI、构建、格式调整、依赖升级、仅文档变更以及其他对用户没有必要说明的内容。不要创建 Breaking Changes、Highlights、Maintenance、Documentation、Dependencies 或其他章节。若一个不兼容变更本身也是必须说明的 Feature 或 Bug Fix，请在对应条目中简洁说明影响，不要为它单独创建章节。
